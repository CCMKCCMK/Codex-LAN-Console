# Codex LAN Console 1.5.0

Codex LAN Console 用安卓手机或 iPhone 查看和控制这台 Windows 电脑上已经登录的 Codex/ChatGPT 编程环境。手机端不需要再登录 OpenAI、Google 或 Microsoft 账号。

## 1.5.0 的主要改进

### 真正的权限模式

- 输入区提供“安全只读”“项目开发”“项目自主”和“完全自主”四个预设，也可以分别设置沙箱范围与审批方式。
- “完全自主”会把任务实际启动为 `danger-full-access + never`：没有 Codex 文件沙箱，也不会逐项请求命令批准。它不是只改变界面文字。
- 这相当于按当前 Windows 用户权限进行远程控制：可以读取、修改或删除文件、运行程序并联网。手机或配对令牌失陷时风险等同于电脑被远程控制；不需要时应关闭“自动允许”，并停止桥接服务。
- 企业或管理员下发的强制策略仍然优先；若策略禁止完全访问，桥接端会明确返回 403，不会伪装成功或尝试绕过。
- 电脑端另一个 Codex 进程已经持有并正在执行的任务仍不能被桥接端劫持。需要完整的手机控制时，应从 Console 启动或继续任务。

### 一键批准与自动批准

- “一键允许全部待审批”会处理当前队列中的命令、文件修改和细粒度权限请求。
- “自动允许所有审批”是单独的高风险开关。开启后，桥接端会对后续支持的审批直接选择允许，并在重启后保持开启，直到你手动关闭。
- 普通提问、`request_user_input` 和 MCP 表单不会被自动填写。
- 已修复细粒度权限请求的协议格式；浏览器、网络或项目外目录请求现在会授予 Codex 实际请求的权限和正确的作用范围。

### 超大历史内存保护

- 恢复任务时只加载任务元数据，消息内容始终通过游标按页读取；旧客户端或旧 Codex 不支持安全分页时会明确要求更新，不再回退到一次性读取全部历史。
- 桥接端直接按 UTF-8 流式解析 Codex 消息，并为单条响应设置 32 MiB 硬上限。异常巨大的响应会被切断并自动重连，不会再把数 GB 的 JSON 同时复制成多份内存对象。
- 使用约 1.35 GB 的真实历史任务从最新页连续翻到最早页回归后，桥接端峰值约 356 MB；空闲冷启动约 67 MB，没有再出现 8 GB 级膨胀。

### iOS 客户端

- 新增原生 Swift/WKWebView 客户端，复用同一套任务、审批、上传、下载、Markdown、命令和权限界面。
- GitHub Actions 在 macOS 上编译无签名的真机 IPA 和模拟器 App；项目不保存任何 Apple 证书或开发者账号。
- iPhone 真机安装必须由使用者使用自己的 Apple Account/Developer Team 签名。完整步骤见 [`ios/README.md`](ios/README.md)。
- iOS 会在 App 活跃以及系统给予后台刷新机会时检查任务并发出本地通知。Apple 不允许普通未配置推送服务的 App 像 Android 前台服务那样持续后台轮询，因此锁屏后的即时性不能保证。

## 1.4.0 的主要改进

### 内存与历史记录

- 任务详情只加载最新 6 轮摘要；需要时再逐页加载更早内容。
- 大体积图片、Base64、工具结果和超长文本不会作为完整历史反复传到手机。
- 刷新请求不会重叠；运行中的详情约 6 秒刷新一次，空闲详情约 15 秒，其他页面约 15 秒。
- 任务列表直接读取状态数据库，不再为每次刷新扫描全部 JSONL 历史。

### 权限与实时状态

- 输入区可以选择只读、项目内修改或完全访问电脑，并独立选择自动安全审核、手动询问、不逐项询问或严格询问。
- “不逐项询问”不会突破所选文件权限；完全访问电脑会先显示一次明确警告。
- 任务状态区分正在运行、等待批准、等待回答、已完成、已停止、出错和状态不可见。
- 独立桥接进程看不到的桌面任务不会再被误报为空闲；Console 会根据桌面任务日志显示明确的外部运行状态，但不会伪装成可中断。后端也会拒绝对仍由电脑端持有的任务并发发送、停止、压缩或修改目标。

## 1.3.0 的主要改进

### 后台任务通知

- 远程 Codex 任务完成、失败或中断时，安卓手机会发出系统通知。
- 通过手机 Console 启动或继续的任务在等待批准、输入或决定时会立即提醒，常规命令/文件审批和提问可直接在手机处理。
- 电脑端 ChatGPT/Codex 自己启动的任务也会收到完成通知；当它调用 `request_user_input` 等待回复时，手机会提示回电脑处理。
- 手机端通过低功耗长轮询在后台工作；与页面是否打开无关，断网后会自动退避并重连。
- 任务事件、游标和最近通知 ID 都会持久化，避免重连、重启或实时/扫描同时发现状态时重复响铃。
- 后台通知使用的配对令牌与电脑地址由 Android Keystore 加密保存；网页配对完成后只保留 HttpOnly 会话 Cookie，不再把完整令牌长期放在 WebView 存储中。锁屏只显示通用提示，不显示任务内容。
- 电脑端每 30 秒做一次低负载状态复核，只读取最近最多 5 轮的状态摘要，不会周期性加载完整历史；手机 Console 自己启动的任务仍通过实时事件立即提醒，同一扫描间隔内连续完成多轮也不会只保留最后一轮。

### 如何开启

1. 覆盖安装 `Codex-LAN-Console-v1.5.0.apk`，然后打开手机 App。
2. 在“概览”页点击“开启通知”，并允许 Android 发送通知。
3. 点击“试一下”验证声音和震动。小米/Redmi 如提示后台限制，再点击“后台设置”允许持续运行。

安卓会显示一条低优先级的“Codex 后台提醒已开启”常驻通知，这是 Android 8–16 保持及时后台监听所必需的可见提示。它本身不会反复响铃；只有任务事件使用有声通知频道。通知声音仍遵循系统静音、勿扰模式和频道设置。

## 1.2.1 的主要改进

### 原生返回手势

- 安卓左右边缘的系统返回手势现在可以直接用于 Console，不必寻找屏幕上的返回按钮。
- 返回顺序为：先关闭当前浮层，再从任务详情回到任务列表，然后按页面访问顺序逐级返回；到达概览首页后，再次返回才退出 App。
- 屏幕上的“返回”按钮与系统手势使用同一套逻辑，刷新任务详情后也能恢复正确的返回层级。

## 1.2.0 的主要改进

### 安全查看和下载交付文件

- 任务消息里的 Markdown 会正常渲染，不再显示为原始文本。
- Codex 输出的文件路径和链接会显示为文件卡片。文档、图片、视频、APK、源码压缩包和使用说明都可以在手机上打开或下载。
- 交互式 HTML 交付物可以加载同目录下的样式、脚本、图片等相对资源，但运行在隔离的预览环境中，不能获得 Console 的权限。
- 工作区文件只能从当前任务目录内解析。查看和下载地址要求设备已经配对，并使用临时、不可猜测的访问凭证。
- 安卓下载会携带配对凭证，文件保存到系统“下载”目录；APK 下载完成后可以交给安卓安装器继续安装。

### 手机上传附件

- 输入框支持一次选择并上传多个文档、图片或视频。
- 安卓 App 也可以直接拍照或录制视频后添加为附件，而且不需要申请读取整个相册的权限。
- 图片会作为图像输入交给 Codex；其他文件会作为 Codex 能在 Windows 端读取的文件引用发送。
- 每次最多 10 个文件；单个文件最大 128 MiB；一次请求合计最大 256 MiB。
- 上传副本保存在 `%LOCALAPPDATA%\CodexLanConsole\Uploads`，最多保留 30 天，之后自动清理。需要长期保存的文件应保留原件。

### 命令、Skill 和 Tool 面板

在输入框键入 `/` 即可打开命令面板。

- `/go <指令>`：向当前任务发送普通指令。
- `/skills`：读取 Codex 当前可用的 Skills，并将所选 Skill 作为结构化引用加入请求。
- `/tools`：查看当前可用的 MCP/工具，并在请求中明确要使用的工具。
- `/goal`、`/compact`、`/status`、`/stop`、`/new`、`/fix`、`/explain` 和 `/verify`：处理常用的任务管理操作。
- 键入 `$` 也会显示 Skill 建议。用户不需要手写 Codex 协议所用的 JSON。

### 发送可靠性和错误诊断

- Windows 桥接端已经适配当前 Codex app-server 要求的输入格式。
- 桥接端重启后，如果历史任务尚未载入，会先恢复任务再发送新消息。这修复了直接向未载入任务发送消息时常见的 `500` 错误。
- 当前任务已经在运行时，Console 可以把新要求追加到正在运行的任务，避免创建互相冲突的新一轮。
- 如果请求仍然失败，界面会显示操作名称、状态、请求 ID 和安全的错误详情。可凭请求 ID 在 Windows 日志中定位对应问题，不会暴露配对令牌。

## 发布文件

- 源码目录中的 Windows 桥接端：`release\WindowsBridge\CodexLanBridge.exe`
- 解压发布包后的 Windows 桥接端：`WindowsBridge\CodexLanBridge.exe`
- 安卓 App：`Codex-LAN-Console-v1.5.0.apk`
- iOS 真机包：GitHub Actions 生成的 `Codex-LAN-Console-iOS-v1.5.0-unsigned.ipa`（必须自行签名）
- iOS 模拟器包：GitHub Actions 生成的 `Codex-LAN-Console-iOS-v1.5.0-simulator-unsigned.zip`
- iOS 自行签名源码：`Codex-LAN-Console-iOS-v1.5.0-source.zip`（推荐在 Mac 上解压后按 `ios/README.md` 用自己的 Team 构建）
- 本地端口：TCP 8787
- 配对数据、通知事件和上传文件：`%LOCALAPPDATA%\CodexLanConsole`
- 安卓要求：Android 8.0 或更高版本
- iOS 要求：iOS 16 或更高版本

## 使用唯一的 BAT 管理程序

日常只使用桌面的 `Codex LAN Console 开关.bat`。桥接端按需运行，不需要随 Windows 自动启动。

1. 选择 `1` 启动桥接端。
2. 选择 `3` 查看当前六位配对码、Tailscale 地址和局域网地址。
3. 不再需要远程访问时，选择 `2` 停止桥接端。
4. 选择 `4` 刷新状态。

需要在终端快速检查时，可以运行 `Codex-LAN-Toggle.bat status`。管理程序在源码目录中会优先使用 `release\WindowsBridge`，在解压后的发布包中会使用 `WindowsBridge`。

## 通过局域网或 Tailscale 连接

手机和电脑连接同一可信 Wi-Fi 或有线局域网时，使用 BAT 管理程序显示的局域网地址，例如 `http://192.168.x.x:8787`。

需要在外网访问时，应在 Windows 和安卓上分别安装 Tailscale，并让两台设备加入同一个 tailnet，然后使用管理程序显示的 `http://100.x.x.x:8787` 地址。Tailscale 不内置在 APK 中，因此可以独立更新和管理。

不要在路由器上把 8787 端口转发到公网，也不要把桥接端直接暴露在互联网中。本程序面向可信局域网、Tailscale、Headscale 或其他私有 WireGuard 网络。

局域网 HTTP 适合你完全信任的家庭网络。跨网络或公共 Wi-Fi 场景优先使用 Tailscale/Headscale；它会在手机和电脑之间建立加密隧道，避免配对凭据以普通局域网流量暴露。

当 Codex 输出使用 `localhost`、`127.0.0.1`、`0.0.0.0` 或 `*.localhost` 的 HTTP 链接时，Console 会把链接改写为手机能够访问的地址；如果原服务只允许本机访问，还会创建临时、需要认证的转发。由于证书通常只对 localhost 有效，本地 HTTPS 链接不一定能够安全改写。

## 安装或升级安卓 App

1. 把 `Codex-LAN-Console-v1.5.0.apk` 传到手机；已经配对的旧版本也可以直接下载这个 APK。
2. 打开 APK，并在安卓提示时只允许从当前来源安装。
3. 打开 Codex LAN Console，输入 BAT 管理程序显示的一个地址。
4. 输入当前六位配对码。

升级时直接覆盖安装，不要先卸载旧版本。只要签名一致，覆盖安装会保留 App 数据和现有配对。

## 在 iPhone 上自行签名

Windows 不能为 iPhone 生成可直接安装的受信任签名。仓库中的 macOS 工作流只负责验证源码并生成无签名构建物，不接收、不保存也不代管 Apple 证书。

最稳妥的安装方式是在 Mac 上用 Xcode 打开 `ios/CodexLanConsole.xcodeproj`（若项目文件尚未生成，先按 `ios/README.md` 运行 XcodeGen），把 Bundle Identifier 改成自己的唯一值，选择自己的 Team，保持 Automatically manage signing 开启，然后连接 iPhone 运行。详细步骤和 GitHub Actions 用法见 [`ios/README.md`](ios/README.md)。

## 常见问题

- **手机无法连接：** 确认 BAT 管理程序显示 `RUNNING`。使用 Tailscale 时，确认两台设备在同一个 tailnet 中在线；使用局域网时，确认手机和电脑位于同一个可信网络。
- **后台不提醒：** 先在概览页确认状态为“后台运行中”，再点击“试一下”。小米/Redmi 还应在“后台设置”中允许自启动/后台运行并将电量策略设为不限制。强行停止 App 后 Android 不允许它自行恢复，需重新打开一次。
- **通知提示必须回电脑处理：** 常规命令、文件修改、细粒度权限审批和提问都可直接在手机处理。少数 MCP 扩展表单无法从当前协议安全还原完整选项，手机仍会提醒并打开对应任务，但不会自动猜测答案。
- **电脑端单独启动的任务：** 当前 Codex 的待审批状态属于启动它的桌面进程，另一个桥接进程不能安全代答。Console 会通知它的完成结果，并能识别桌面任务的明确提问；桌面进程独有的系统审批仍需在电脑处理。需要完整手机审批时，请从手机 Console 启动或继续该任务。
- **看不到配对码：** 先启动桥接端，再选择 `3`。当前配对码也保存在 Windows 的 `%LOCALAPPDATA%\CodexLanConsole\pairing.txt`。
- **文件无法上传：** 确认不超过 10 个文件、单个 128 MiB、合计 256 MiB，并在网络稳定后重试。
- **文件卡片无法再打开：** 临时下载凭证可能已经过期。重新载入任务即可申请新的凭证。手机上传的副本最多保留 30 天。
- **发送请求失败：** 打开错误详情，报告问题时同时保留请求 ID、操作名称和错误文字。

## 存储和卸载

安卓 SDK 和 JDK 只在重新编译 APK 时需要，桥接端运行时不会使用它们。iOS 构建只在 GitHub 的 macOS runner 或安装了 Xcode 的 Mac 上进行，不会在 Windows 上留下 Xcode 缓存。

仅在确实要移除 Console 时运行 `Uninstall.ps1`。它会清除配对令牌、上传副本以及旧的自动启动项，但不会静默删除项目目录或 APK。
